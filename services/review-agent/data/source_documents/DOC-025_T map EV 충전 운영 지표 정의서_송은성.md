# 01. 운영 정책 개요

## 1-1. 목적

본 문서는 T map EV 충전 서비스의 운영 정책과 주요 운영 지표(KPI)를 정의하여 서비스 품질을 지속적으로 관리하고 운영 의사결정의 기준을 마련하는 것을 목적으로 한다.

운영 정책은 EV 충전소 검색, 충전 상태 정보 제공, 운영 데이터 관리 및 서비스 성과 측정을 포함하며, 운영 조직과 개발 조직이 동일한 기준으로 서비스를 관리할 수 있도록 한다.

---

## 1-2. 적용 범위

본 정책은 EV 충전 서비스의 다음 기능에 적용한다.

| 기능 | 적용 여부 |
| --- | --- |
| 충전소 검색 | O |
| 충전기 정보 조회 | O |
| 충전 가능 여부 조회 | O |
| 즐겨찾기 | O |
| 운영 통계 | O |
| 운영 대시보드 | O |

충전 결제 서비스 및 멤버십 운영 정책은 본 문서의 적용 범위에서 제외한다.

---

## 1-3. 운영 목표

운영 목표는 다음과 같다.

- 충전소 정보의 정확성 유지
- 검색 품질 향상
- 충전소 이용 편의성 개선
- 운영 장애 최소화
- 데이터 기반 운영 체계 구축

---

## 1-4. 운영 원칙

서비스 운영은 다음 원칙을 따른다.

- 실시간 데이터 기반 운영
- 운영 상태의 지속적 모니터링
- 사용자 행동 데이터 기반 개선
- 운영 정책의 일관성 유지
- 장애 발생 시 신속한 대응

---

## 1-5. 사용자 정의

본 문서에서 **회원**은 EV 충전 서비스를 이용하는 T map 로그인 계정을 의미한다.

회원의 검색, 조회, 즐겨찾기, 충전 이력은 운영 데이터 분석의 기준으로 활용한다.

회원 활동 정보는 운영 KPI 산출 및 서비스 개선을 위한 분석 데이터로 사용한다.

---

# 02. 제약사항

## 2-1. 서비스 범위

이번 릴리스에서는 EV 충전 서비스의 운영 정책과 운영 지표 개선을 대상으로 한다.

충전 결제 기능, 멤버십 정책 변경 및 외부 제휴 서비스는 이번 범위에 포함하지 않는다.

---

## 2-2. 기능 제약

이번 릴리스에서는 기존 **회원**을 대상으로 운영 기능을 제공한다.

신규 회원 확보를 위한 가입 유도 기능, 신규 회원 대상 프로모션 및 신규 가입 기능은 이번 개발 범위에 포함하지 않는다.

---

## 2-3. 데이터 제약

운영 지표는 서비스에서 수집되는 표준 로그만 활용한다.

외부 기관 데이터 및 제휴사 운영 데이터는 KPI 산출 대상에서 제외한다.

---

## 2-4. 운영 제약

운영 정책 변경은 관리자 권한에서만 가능하다.

일반 운영자는 운영 현황 조회 및 리포트 확인 기능만 사용할 수 있다.

---

## 2-5. 성능 제약

운영 통계는 배치 데이터를 기준으로 생성한다.

실시간 운영 대시보드와 통계 리포트 간 일부 수치 차이가 발생할 수 있으며, 공식 운영 지표는 배치 데이터를 기준으로 관리한다.

---

# 03. 운영 정책

## 3-1. 충전소 정보 관리

충전소 정보는 운영 상태가 정상인 데이터만 사용자에게 제공한다.

운영 대상은 다음과 같다.

| 상태 | 운영 대상 |
| --- | --- |
| 운영 중 | O |
| 점검 중 | O |
| 운영 종료 | X |
| 삭제 예정 | X |

운영 상태 변경 시 검색 데이터와 운영 통계를 함께 갱신한다.

---

## 3-2. 충전기 정보 관리

충전기별 운영 정보는 다음 항목을 관리한다.

- 충전기 유형
- 충전 출력
- 운영 상태
- 사용 가능 여부
- 마지막 갱신 시각

운영 데이터는 일정 주기로 동기화한다.

---

## 3-3. 이용 로그 수집

운영 분석을 위해 다음 이벤트를 수집한다.

| 이벤트 | 수집 여부 |
| --- | --- |
| 충전소 검색 | O |
| 충전소 조회 | O |
| 길안내 시작 | O |
| 충전 시작 | O |
| 충전 완료 | O |
| 즐겨찾기 등록 | O |

모든 이벤트는 운영 로그 저장소에 기록한다.

---

## 3-4. 운영 모니터링

운영자는 다음 항목을 실시간으로 확인한다.

- 검색 이용 건수
- 충전 완료 건수
- 충전 실패 건수
- 운영 장애 현황
- API 응답시간
- 서버 상태

---

## 3-5. 운영 보고

운영 현황은 주간 및 월간 단위로 집계한다.

보고 항목은 다음을 포함한다.

- 주요 운영 지표
- 장애 발생 현황
- 이용 추이
- 개선 과제
- 차기 운영 계획

---

# 04. 운영 데이터 관리

## 4-1. 운영 데이터 수집

운영 데이터는 다음 항목을 기준으로 수집한다.

| 항목 | 내용 |
| --- | --- |
| 충전소 조회 | 조회 건수 |
| 검색 수행 | 검색 횟수 |
| 길안내 실행 | 길안내 요청 건수 |
| 충전 시작 | 충전 시작 건수 |
| 충전 완료 | 충전 완료 건수 |
| 오류 발생 | 시스템 오류 건수 |

운영 로그는 일 단위로 적재하며 분석 시스템으로 전송한다.

---

## 4-2. 데이터 품질 관리

운영 데이터는 다음 기준을 만족해야 한다.

- 중복 로그 제거
- 필수 항목 누락 여부 확인
- 비정상 이벤트 제외
- 시간 정보 표준화

품질 검증 완료 후 운영 리포트 생성에 활용한다.

---

## 4-3. 데이터 보관 정책

운영 데이터는 내부 정책에 따라 안전하게 보관한다.

데이터 접근 권한은 운영 조직별 역할에 따라 관리하며, 개인정보는 식별이 불가능한 형태로 저장한다.

---

## 4-4. 운영 리포트

운영 리포트는 다음 항목을 포함한다.

- 일간 운영 현황
- 주간 성과 분석
- 월간 KPI 분석
- 장애 발생 이력
- 개선 과제

리포트는 운영 포털에서 조회할 수 있도록 제공한다.

---

# 05. 통계 화면

## 5-1. 운영 대시보드

운영 대시보드는 주요 운영 현황을 한 화면에서 확인할 수 있도록 구성한다.

제공 항목은 다음과 같다.

- 검색 건수
- 충전 완료 건수
- 충전 성공률
- 운영 장애 현황
- API 응답시간

---

## 5-2. KPI 현황

운영 KPI는 기간별 추이를 함께 제공한다.

다음 항목을 기본으로 표시한다.

| KPI | 집계 주기 |
| --- | --- |
| 검색 이용 건수 | 일 |
| 평균 충전 완료율 | 월 |
| 충전 성공률 | 주 |
| 즐겨찾기 등록 건수 | 월 |
| 검색 성공률 | 일 |

**이용자**의 평균 충전 완료율은 월 단위로 집계하며, 충전 성공률은 주간 운영 리포트에 포함한다.

---

## 5-3. 운영 통계 조회

운영자는 기간 조건을 선택하여 통계를 조회할 수 있다.

조회 조건은 다음을 지원한다.

- 일별
- 주별
- 월별
- 분기별

조회 결과는 화면 및 다운로드 기능을 함께 제공한다.

---

## 5-4. 통계 시각화

운영 통계는 다음 형태로 제공한다.

- 막대 그래프
- 선 그래프
- 원형 차트
- 표(Table)

시각화 기준은 운영 포털의 공통 UI 정책을 따른다.

---

## 5-5. 다운로드 기능

운영 통계는 Excel 형식으로 다운로드할 수 있다.

다운로드 파일에는 조회 조건과 생성 시각을 함께 포함한다.

---

# 06. 성공 지표

## 6-1. 핵심 KPI

서비스 운영 성과는 다음 KPI를 기준으로 관리한다.

| KPI | 목표 |

| **신규 회원 가입 수** | **30% 증가** |
| 운영 장애 건수 | 지속 감소 |

---

## 6-2. 운영 성과 지표

운영 품질은 다음 항목을 지속적으로 관리한다.

- 검색 이용률
- 충전 완료율
- 즐겨찾기 이용률
- 운영 안정성
- 데이터 정확성

운영 결과는 월간 운영 회의에서 검토한다.

---

## 6-3. 서비스 품질 목표

품질 목표는 다음 기준을 따른다.

| 항목 | 목표 |
| --- | --- |
| 검색 API 성공률 | 99.9% 이상 |
| 운영 데이터 정확도 | 99% 이상 |
| 통계 생성 성공률 | 99% 이상 |
| 리포트 생성 성공률 | 100% |

---

## 6-4. 운영 개선 관리

성과 지표 분석 결과를 기반으로 개선 과제를 도출한다.

개선 과제는 우선순위를 설정하여 운영 계획에 반영하며, 적용 이후 KPI 변화를 지속적으로 확인한다.

# 07. 운영 관리 체계

## 7-1. 운영 권한

| 권한 | 조회 | 수정 | 배포 |
| --- | --- | --- | --- |
| 일반 운영자 | O | X | X |
| 서비스 운영자 | O | O | X |
| 관리자 | O | O | O |

권한 변경 이력은 감사 로그에 기록한다.

---

## 7-2. 장애 대응

운영 장애 발생 시 다음 절차를 수행한다.

1. 장애 감지
2. 운영 알림 발송
3. 원인 분석
4. 서비스 복구
5. 운영 결과 보고

장애 종료 후 재발 방지 대책을 수립한다.

---

## 7-3. 운영 모니터링

운영자는 다음 항목을 상시 모니터링한다.

- 운영 KPI
- 시스템 상태
- API 응답시간
- 장애 발생 현황
- 데이터 적재 상태

기준치를 초과하는 이상 징후가 발생할 경우 운영 알림을 생성한다.

---

## 7-4. 변경 이력 관리

운영 정책 변경 사항은 변경 일시, 변경 내용, 변경 담당자를 포함하여 관리한다.

모든 변경 이력은 운영 감사 정책에 따라 보관하며, 운영 조직에서 이력을 조회할 수 있도록 제공한다.
