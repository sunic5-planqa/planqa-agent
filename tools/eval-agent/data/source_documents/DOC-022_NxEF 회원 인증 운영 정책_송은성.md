# 01. 회원 인증 정책 개요

## 1-1. 목적

본 문서는 NxEF 서비스의 회원 인증 절차와 운영 기준을 정의하여 안전한 사용자 인증 환경을 제공하고, 인증 과정에서 발생 가능한 예외 상황에 대한 처리 기준을 명확히 하는 것을 목적으로 한다.

회원 인증은 서비스 이용자의 신원을 확인하고 계정의 무단 사용을 방지하기 위한 필수 절차이며, 인증 성공 이후 서비스 접근 권한을 부여한다.

---

## 1-2. 적용 범위

본 정책은 다음 기능에 적용한다.

| 구분 | 적용 여부 |
| --- | --- |
| 신규 회원가입 | O |
| 로그인 | O |
| 휴대폰 본인 인증 | O |
| 비밀번호 재설정 | O |
| 계정 잠금 해제 | O |
| 기기 변경 로그인 | O |
| 민감 정보 변경 | O |

---

## 1-3. 인증 수단

NxEF에서 지원하는 인증 방식은 다음과 같다.

| 인증 방식 | 적용 대상 | 비고 |
| --- | --- | --- |
| 휴대폰 본인 인증 | 회원가입 | 기본 인증 |
| SMS 인증번호 | 로그인 추가 인증 | 선택 적용 |
| PASS 인증 | 회원가입 | 지원 사업자 대상 |
| 공동인증 연계 | 일부 서비스 | 정책 적용 시 |
| 생체 인증 | 모바일 앱 | 기기 지원 시 |

서비스 정책 변경에 따라 신규 인증 수단을 추가할 수 있다.

---

## 1-4. 인증 유효시간

인증 수단별 유효시간은 다음 기준을 적용한다.

| 항목 | 기준 |
| --- | --- |
| 인증번호 유효시간 | 3분 |
| 인증 세션 유지 | 10분 |
| 로그인 인증 유지 | 24시간 |
| 추가 인증 재요청 제한 | 30초 |

유효시간이 경과한 인증번호는 사용할 수 없으며 신규 인증번호를 발급받아야 한다.

---

## 1-5. 인증 성공 기준

다음 조건을 모두 만족한 경우 인증 성공으로 판단한다.

- 정상적인 인증 요청
- 인증번호 일치
- 유효시간 내 입력
- 인증 횟수 초과 아님
- 차단 대상 사용자 아님

모든 조건을 만족하면 인증 완료 상태를 부여한다.

---

## 1-6. 인증 실패 기준

다음 조건에서는 인증 실패로 처리한다.

- 인증번호 불일치
- 인증번호 만료
- 요청 횟수 초과
- 비정상 접근 탐지
- 통신사 인증 실패
- 인증 서버 오류

인증 실패 사유는 로그에 저장하며 운영 모니터링 대상으로 관리한다.

---

# 02. 인증 오류 개선

## 2-1. 문제 정의

최근 회원가입 과정에서 휴대폰 본인 인증 단계의 인증번호 입력 시간이 초과되어 회원가입을 중단하는 사례가 지속적으로 증가하고 있다.

특히 인증번호 수신 지연 또는 입력 시간 초과로 인해 인증을 완료하지 못하고 이탈하는 사용자가 증가하고 있으며, 동일 사용자가 반복적으로 인증을 재시도하는 사례도 함께 증가하는 추세이다.

운영 로그 분석 결과 인증번호 입력 제한 시간이 만료되는 시점에서 회원가입 이탈률이 가장 높게 나타났다.

---

## 2-2. 개선 방안

회원가입 화면의 버튼 색상을 서비스 메인 컬러와 일관성 있게 변경한다.

인증 화면의 레이아웃을 단순화하여 입력 영역의 가시성을 향상시킨다.

안내 문구의 글자 크기를 조정하고 버튼 간 간격을 확대하여 화면의 가독성을 개선한다.

모바일 환경에서는 화면 상단 여백을 축소하여 인증 화면의 전체 구성을 간결하게 제공한다.

---

## 2-3. 운영 모니터링

인증 오류 개선 이후 다음 지표를 지속적으로 모니터링한다.

| 지표 | 측정 기준 |
| --- | --- |
| 인증 성공률 | 일 단위 |
| 인증 실패율 | 일 단위 |
| 인증 재시도율 | 일 단위 |
| 인증 API 오류율 | Hourly |
| 화면 진입 수 | Daily |

운영 결과는 주간 보고서를 통해 검토한다.

---

## 2-4. 개선 효과 검증

개선 사항 적용 이후에는 운영 지표를 기준으로 효과를 분석한다.

분석 항목은 다음과 같다.

- 인증 완료율 변화
- 회원가입 완료율
- 인증 화면 이탈률
- 평균 인증 소요시간
- 인증 오류 발생 건수

동일 기간 이전 데이터와 비교하여 효과를 검증한다.

---

## 2-5. 향후 개선 방향

운영 결과를 기반으로 다음 항목을 검토한다.

- 인증 화면 접근성 향상
- 다국어 인증 화면 제공
- 인증 안내 문구 개선
- 사용자 피드백 반영
- 인증 화면 디자인 고도화

---

# 03. 회원가입 절차

## 3-1. 회원가입 시작

사용자는 회원가입 화면에서 필수 약관을 확인하고 가입 절차를 시작한다.

필수 약관은 모두 동의해야 다음 단계로 이동할 수 있으며, 선택 약관은 사용자의 선택에 따라 동의 여부를 결정할 수 있다.

필수 입력 정보는 다음과 같다.

| 항목 | 필수 여부 |
| --- | --- |
| 이름 | O |
| 휴대폰 번호 | O |
| 비밀번호 | O |
| 이메일 | O |
| 생년월일 | O |

---

## 3-2. 본인 인증

회원가입 진행을 위해 사용자는 휴대폰 본인 인증을 수행한다.

인증번호는 등록된 휴대폰 번호로 발송하며, 사용자는 유효시간 내 인증번호를 입력해야 한다.

인증번호는 최대 5회까지 입력 가능하며, 초과 시 일정 시간 동안 재시도가 제한된다.

PASS 인증을 지원하는 환경에서는 PASS 인증을 사용할 수 있으며, 서비스 정책에 따라 다른 인증 방식을 추가 제공할 수 있다.

---

## 3-3. 회원가입 완료

회원가입이 완료되면 서비스 메인 화면으로 이동한다.

자동 로그인 정책이 활성화된 경우 로그인 상태를 유지하며 메인 서비스를 즉시 이용할 수 있다.

회원가입 완료 이후 환영 메시지를 노출하고 주요 서비스 이용 안내를 제공한다.

---

## 3-4. 가입 취소

사용자는 회원가입 진행 중 언제든 가입 절차를 종료할 수 있다.

가입 취소 시 입력 중인 정보는 저장하지 않으며 초기 화면으로 이동한다.

---

# 04. 로그인 인증 운영 정책

## 4-1. 로그인 절차

회원 로그인은 등록된 계정 정보와 인증 정보를 기반으로 수행한다.

로그인 절차는 다음 순서를 따른다.

1. 로그인 화면 진입
2. 아이디(또는 이메일) 입력
3. 비밀번호 입력
4. 계정 정보 검증
5. 추가 인증 대상 여부 확인
6. 로그인 완료

계정 검증이 완료된 경우 사용자 세션을 생성하고 서비스 이용 권한을 부여한다.

---

## 4-2. 추가 인증 정책

다음 조건에 해당하는 경우 추가 인증을 수행한다.

| 조건 | 추가 인증 여부 |
| --- | --- |
| 신규 기기 로그인 | O |
| 해외 IP 로그인 | O |
| 장기간 미접속 후 로그인 | O |
| 일반 로그인 | X |
| 동일 기기 재로그인 | X |

추가 인증은 SMS 인증번호 또는 PASS 인증을 우선 제공한다.

---

## 4-3. 로그인 실패 정책

다음 조건에서는 로그인 실패로 처리한다.

- 비밀번호 불일치
- 존재하지 않는 계정
- 인증 실패
- 계정 잠금 상태
- 관리자 차단 계정

로그인 실패 시 실패 사유는 내부 로그에 기록하며, 사용자에게는 보안 정책에 따라 일반화된 안내 메시지를 제공한다.

---

## 4-4. 로그인 시도 제한

비밀번호 입력 오류가 반복될 경우 계정을 보호하기 위해 로그인 시도를 제한한다.

| 실패 횟수 | 처리 방식 |
| --- | --- |
| 1~4회 | 재입력 허용 |
| 5회 | 계정 일시 잠금 |
| 10회 이상 | 관리자 확인 필요 |

계정 잠금 해제는 본인 인증 완료 후 수행한다.

---

## 4-5. 세션 관리 정책

로그인 성공 시 사용자 세션을 생성한다.

세션은 다음 기준으로 관리한다.

| 항목 | 기준 |
| --- | --- |
| 기본 세션 유지 | 24시간 |
| 미사용 세션 만료 | 30분 |
| 로그아웃 | 즉시 세션 종료 |
| 비밀번호 변경 | 모든 세션 종료 |

동일 계정의 다중 로그인 허용 여부는 서비스 정책에 따라 설정할 수 있다.

---

## 4-6. 기기 변경 로그인

기존에 등록되지 않은 기기에서 로그인하는 경우 추가 인증을 수행한다.

기기 정보는 단말 식별값을 기준으로 관리하며, 인증 완료 후 신뢰 기기로 등록할 수 있다.

신뢰 기기 등록 이후에는 일정 기간 추가 인증을 생략할 수 있다.

---

# 05. 인증 오류 대응 정책

## 5-1. 인증번호 불일치

사용자가 입력한 인증번호가 발급된 인증번호와 일치하지 않는 경우 인증 실패로 처리한다.

인증 실패 횟수는 누적 관리하며, 최대 허용 횟수를 초과하면 일정 시간 동안 인증 요청을 제한한다.

---

## 5-2. 인증번호 만료

인증번호 유효시간이 초과된 경우 해당 인증번호는 사용할 수 없다.

사용자는 인증번호 재발급 기능을 통해 새로운 인증번호를 요청해야 하며, 기존 인증번호는 즉시 무효 처리한다.

---

## 5-3. SMS 발송 실패

통신사 장애 또는 외부 SMS 게이트웨이 오류로 인증번호 발송이 실패한 경우 다음 순서로 처리한다.

1. 자동 재발송
2. PASS 인증 안내
3. 일정 시간 이후 재시도 안내

운영자는 SMS 발송 성공률을 실시간으로 모니터링한다.

---

## 5-4. 인증 서버 장애

인증 서버 장애 발생 시 인증 요청을 일시 중단하고 장애 안내 화면을 제공한다.

장애 복구 이후에는 인증 서비스를 정상 재개하며, 장애 발생 내역은 운영 로그에 기록한다.

---

## 5-5. 비정상 인증 시도

다음 조건은 비정상 인증으로 판단한다.

- 동일 IP의 과도한 인증 요청
- 단시간 반복 인증 실패
- 비정상 User-Agent
- 자동화 프로그램 탐지
- 차단 대상 네트워크 접근

비정상 요청은 운영 정책에 따라 차단하거나 추가 인증 대상으로 분류한다.

---

## 5-6. 운영 알림 정책

다음 이벤트 발생 시 운영자에게 알림을 전송한다.

- 인증 성공률 급감
- SMS 발송 실패율 증가
- 인증 API 장애
- 인증 서버 응답 지연
- 비정상 인증 시도 급증

알림은 운영 모니터링 시스템과 연계하여 실시간으로 제공한다.

---

# 06. 운영 관리 정책

## 6-1. 운영 권한

회원 인증 정책 변경 권한은 관리자 계정으로 제한한다.

| 권한 | 조회 | 수정 | 배포 |
| --- | --- | --- | --- |
| 일반 운영자 | O | X | X |
| 서비스 운영자 | O | O | X |
| 관리자 | O | O | O |

권한 변경 이력은 감사 로그에 저장한다.

---

## 6-2. 감사 로그 관리

회원 인증과 관련된 주요 작업은 감사 대상으로 관리한다.

저장 항목은 다음과 같다.

- 작업자
- 작업 시각
- 변경 대상
- 변경 전·후 값
- 변경 사유
- 적용 버전

감사 로그는 운영 정책에 따른 보관 기간 동안 유지한다.

---

## 6-3. 개인정보 보호

회원 인증 과정에서 수집되는 개인정보는 개인정보 보호 정책에 따라 관리한다.

휴대폰 번호 등 개인 식별 정보는 암호화하여 저장하며, 인증 처리에 필요한 최소 범위에서만 활용한다.

운영자는 권한이 부여된 경우에만 관련 정보를 조회할 수 있다.

---

## 6-4. 운영 모니터링

운영자는 다음 항목을 실시간으로 확인한다.

| 모니터링 항목 | 기준 |
| --- | --- |
| 인증 성공률 | Hourly |
| 인증 실패율 | Hourly |
| SMS 발송 성공률 | Hourly |
| 인증 API 응답시간 | 실시간 |
| 서버 장애 여부 | 실시간 |
| 인증 요청 건수 | Daily |

기준치를 초과하는 이상 징후가 발생하면 운영 알림을 생성한다.

---

## 6-5. 운영 보고 체계

회원 인증 운영 현황은 주간 및 월간 단위로 보고한다.

보고 항목은 다음을 포함한다.

- 인증 성공률 추이
- 인증 오류 발생 현황
- 주요 장애 이력
- 정책 변경 내역
- 개선 과제
- 차기 운영 계획

---

## 6-6. 운영 KPI

| KPI | 목표 |
| --- | --- |
| 인증 성공률 | 99.5% 이상 |
| SMS 발송 성공률 | 99.9% 이상 |
| 인증 API 성공률 | 99.9% 이상 |
| 평균 인증 완료 시간 | 운영 기준 이내 |
| 인증 장애 복구 시간 | SLA 기준 준수 |
| 인증 오류율 | 지속 감소 |

운영 KPI는 월간 단위로 분석하며, 목표 달성 여부를 서비스 운영회의에서 검토한다.
