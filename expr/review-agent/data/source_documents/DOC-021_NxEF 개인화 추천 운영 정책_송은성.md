# 01. 추천 점수 산출 정책

## 1-1. 행동 데이터 반영 기준

NxEF 개인화 추천은 사용자의 최근 서비스 이용 행동을 기반으로 추천 점수를 산출한다. 추천 모델은 다양한 행동 로그를 종합적으로 분석하여 상품별 선호도를 계산하며, 계산 결과는 추천 후보군 생성 및 노출 우선순위 결정에 활용한다.

행동 데이터는 실시간 이벤트 로그와 배치 집계 데이터를 함께 활용하며, 동일 이벤트의 중복 발생 여부를 고려하여 정규화 과정을 수행한다.

| 구분 | 반영 여부 | 설명 | 비고 |
| --- | --- | --- | --- |
| 구매 완료 | O | 실제 구매가 완료된 상품 | 가장 높은 신뢰도 |
| 장바구니 추가 | O | 구매 의도가 높은 행동 | 구매 전 단계 |
| 관심상품 등록 | O | 선호 상품 저장 | 사용자 의도 반영 |
| 상품 상세 조회 | O | 상세 페이지 진입 | 반복 조회 반영 |
| 검색 기록 | O | 검색 키워드 | 최근 검색 우선 |
| 추천 클릭 | O | 추천 결과 선택 | 추천 품질 피드백 |
| 리뷰 작성 | O | 구매 후 리뷰 | 만족도 반영 |

동일 사용자의 반복 이벤트는 이벤트 종류에 따라 최대 반영 횟수를 제한하며, 비정상적인 반복 클릭은 추천 계산에서 제외한다.

---

## 1-2. 행동 가중치 정책

추천 점수 계산 시 행동별 중요도를 반영하기 위해 기본 가중치를 적용한다.

| 행동 유형 | 기본 가중치 |
| --- | --- |
| 구매 | 1.00 |
| 장바구니 | 0.85 |
| 관심상품 | 0.75 |
| 리뷰 작성 | 0.70 |
| 상품 조회 | 0.45 |
| 검색 | 0.35 |
| 추천 클릭 | 0.25 |

동일 상품에 대해 여러 행동이 발생한 경우에는 각 행동 점수를 누적 적용하되, 구매 완료 이후 발생하는 조회 이벤트는 추가 가중치를 부여하지 않는다.

---

## 1-3. 시간 감쇠(Time Decay) 정책

최근 행동일수록 현재 관심사를 반영한다고 판단하여 시간 가중치를 추가 적용한다.

| 행동 발생 시점 | 시간 계수 |
| --- | --- |
| 7일 이내 | 1.00 |
| 8~30일 | 0.80 |
| 31~90일 | 0.60 |
| 91~180일 | 0.35 |
| 180일 초과 | 계산 제외 |

시간 계수는 행동 가중치 계산 이후 적용하며, 최신 행동이 지속적으로 추천 결과에 반영되도록 한다.

---

## 1-4. 카테고리 선호도 계산

사용자의 행동을 상품 단위뿐 아니라 카테고리 단위로 집계한다.

예를 들어 사용자가 최근 30일 동안 스포츠 카테고리 상품을 집중적으로 조회하였다면 동일 카테고리 상품의 추천 점수를 추가 보정한다.

카테고리 선호도는 다음 정보를 활용한다.

- 최근 구매 카테고리
- 최근 조회 카테고리
- 최근 검색 키워드
- 장바구니 상품 카테고리
- 관심상품 카테고리

---

## 1-5. 추천 후보군 생성

추천 점수 계산 이후 후보군을 생성한다.

후보군은 다음 조건을 만족하는 상품으로 구성한다.

- 판매 가능 상태
- 노출 허용 상태
- 재고 존재
- 사용자 차단 대상 아님
- 연령 제한 충족

동일 브랜드 상품이 과도하게 집중되지 않도록 다양성 보정 알고리즘을 함께 적용한다.

---

## 1-6. 최종 추천 순위 산출

최종 추천 순위는 다음 요소를 종합하여 계산한다.

- 행동 가중치
- 시간 가중치
- 카테고리 선호도
- 상품 유사도
- 추천 반응률
- 인기 보정 계수

동일 점수 발생 시에는 다음 우선순위를 적용한다.

1. 최신 등록 상품
2. 판매량 높은 상품
3. CTR 높은 상품

# 02. 추천 대상 데이터 운영 정책

## 2-1. 추천 대상 상품 기준

추천 대상은 운영 중인 정상 상품만 포함한다.

다음 상태의 상품은 추천 계산 대상에서 제외한다.

| 상태 | 추천 포함 여부 |
| --- | --- |
| 판매중 | O |
| 품절 | X |
| 판매종료 | X |
| 검수대기 | X |
| 노출중지 | X |
| 삭제예정 | X |

---

## 2-2. 행동 로그 수집 정책

추천 품질 향상을 위해 다음 이벤트를 수집한다.

| 이벤트 | 저장 여부 |
| --- | --- |
| 조회 | O |
| 클릭 | O |
| 검색 | O |
| 장바구니 | O |
| 구매 | O |
| 리뷰 | O |
| 관심상품 | O |

모든 이벤트는 사용자 식별자와 함께 저장하며, 개인정보는 별도 정책에 따라 암호화하여 관리한다.

---

## 2-3. 데이터 유효기간

행동 데이터는 추천 계산 목적에 한하여 최대 180일까지 활용한다.

180일이 경과한 데이터는 추천 계산 대상에서 제외되며, 통계 분석 목적의 데이터는 별도 저장소에서 관리한다.

---

## 2-4. 데이터 품질 관리

추천 계산 이전 다음 항목을 검증한다.

- 중복 이벤트 제거
- 비정상 클릭 제거
- Bot 이벤트 제거
- 잘못된 상품 ID 제거
- 삭제 회원 이벤트 제거

검증 실패 데이터는 추천 계산에 사용하지 않는다.

---

## 2-5. 추천 데이터 생성 주기

추천 생성은 사용자 활동 수준에 따라 차등 적용한다.

| 사용자 유형 | 생성 주기 |
| --- | --- |
| 일반 사용자 | 1일 1회 |
| 활동 사용자 | 6시간 |
| 신규 사용자 | 가입 직후 |
| 휴면 복귀 | 로그인 즉시 |

추천 생성 완료 후 캐시를 갱신한다.

---

## 2-6. 캐시 운영 정책

추천 결과는 API 응답 성능 확보를 위해 캐시에 저장한다.

기본 캐시 유지시간은 6시간으로 설정하며, 다음 이벤트 발생 시 즉시 갱신한다.

- 구매 완료
- 장바구니 추가
- 관심상품 등록
- 추천 모델 재생성

---

# 03. 추천 노출 정책

## 3-1. 노출 화면

추천 기능은 다음 화면에서 제공한다.

| 화면 | 추천 유형 |
| --- | --- |
| 홈 | 개인화 추천 |
| 검색 | 연관 추천 |
| 상품 상세 | 함께 본 상품 |
| 장바구니 | 추가 구매 추천 |
| 주문 완료 | 후속 추천 |

---

## 3-2. 노출 개수 정책

| 화면 | 최대 개수 |
| --- | --- |
| 홈 | 20 |
| 검색 | 10 |
| 상세 | 10 |
| 장바구니 | 8 |
| 주문 완료 | 6 |

추천 결과가 부족한 경우 인기 상품으로 부족한 개수를 보완한다.

---

## 3-3. 중복 노출 방지

동일 상품은 하나의 화면에서 중복 노출하지 않는다.

여러 추천 영역에서 동일 상품이 선정된 경우 추천 점수가 가장 높은 영역에만 노출한다.

최근 이미 노출된 상품은 일정 기간 동일 위치에 반복 노출되지 않도록 노출 이력을 관리한다.

---

## 3-4. 추천 제외 조건

다음 조건에서는 추천 대상에서 제외한다.

- 이미 구매한 동일 상품
- 판매 종료 상품
- 품절 상품
- 운영 차단 상품
- 사용자 차단 상품
- 연령 제한 미충족 상품
- 지역 제한 상품

---

## 3-5. 추천 결과 부족 시 처리

추천 결과가 최소 노출 개수보다 적은 경우 다음 순서대로 후보를 보완한다.

1. 동일 카테고리 인기 상품
2. 전체 인기 상품
3. 운영자 추천 상품

추천 결과는 화면별 최소 노출 개수를 유지하도록 구성한다.

---

## 3-6. 추천 응답 정책

추천 API는 캐시 데이터를 우선 조회한다.

캐시가 존재하지 않는 경우 추천 서버에서 신규 결과를 조회하며, 추천 생성 실패 시 인기 상품 추천을 반환한다.

추천 API의 목표 응답 시간은 운영 기준 내에서 유지하며, 장애 상황에서는 장애 대응 정책을 따른다.

---

# 04. 추천 운영 예외 정책

## 4-1. 신규 사용자 추천 정책

사용자의 행동 데이터가 충분하지 않은 경우 개인화 추천 대신 대체 추천 정책을 적용한다.

추천 우선순위는 다음과 같다.

| 우선순위 | 추천 방식 | 적용 조건 |
| --- | --- | --- |
| 1 | 카테고리 인기 상품 | 관심 카테고리 존재 |
| 2 | 전체 인기 상품 | 관심 카테고리 없음 |
| 3 | 운영자 추천 상품 | 인기 상품 부족 |
| 4 | 신규 출시 상품 | 운영 정책 적용 시 |

행동 데이터가 일정 기준 이상 누적되면 개인화 추천으로 자동 전환한다.

---

## 4-2. 행동 데이터 부족 정책

최근 행동 데이터가 최소 학습 기준 이하인 경우 추천 모델은 신뢰도가 낮다고 판단한다.

이 경우 추천 계산은 수행하되 부족한 데이터는 인기 상품 점수와 카테고리 선호도를 이용하여 보정한다.

보정 과정에서는 최근 조회 이력이 없는 상품도 추천 후보군에 포함될 수 있다.

---

## 4-3. 추천 서버 장애 정책

추천 서버 장애 발생 시 서비스 중단을 방지하기 위해 단계별 대체 정책을 적용한다.

| 단계 | 처리 방식 |
| --- | --- |
| 1 | 캐시 추천 결과 제공 |
| 2 | 인기 상품 제공 |
| 3 | 운영 추천 상품 제공 |

장애 종료 이후에는 추천 생성 작업을 순차적으로 재수행하며, 장애 기간 동안 발생한 행동 로그를 재반영한다.

---

## 4-4. 데이터 수집 실패

행동 이벤트 일부가 정상적으로 저장되지 않은 경우 추천 생성 시 정상 수집된 데이터만 활용한다.

데이터 누락으로 추천 품질 저하가 예상되는 경우 운영 모니터링 시스템에 경고 이벤트를 생성한다.

---

## 4-5. 운영자 강제 제외

운영자는 특정 상품을 추천 대상에서 즉시 제외할 수 있다.

제외 가능한 주요 사유는 다음과 같다.

- 품질 이슈
- 상품 정보 오류
- 판매 중단 예정
- 긴급 운영 정책 변경
- CS 다발 상품

강제 제외 설정은 추천 생성 시점부터 즉시 반영한다.

---

## 4-6. 추천 모델 배포 중 예외 처리

추천 모델 교체 시 서비스 중단을 방지하기 위해 Blue-Green 배포 방식을 적용한다.

신규 모델 검증 완료 이후 순차적으로 트래픽을 전환하며, 이상 징후 발생 시 기존 모델로 즉시 롤백한다.

---

# 05. 추천 기능 운영 정책

## 5-1. 추천 로그 저장 정책

추천 결과가 사용자에게 노출되는 시점에 다음 정보를 저장한다.

| 저장 항목 | 설명 |
| --- | --- |
| 사용자 ID | 추천 대상 사용자 |
| 상품 ID | 추천 상품 |
| 추천 영역 | 홈/검색/상세 등 |
| 노출 순위 | 화면 내 순위 |
| 추천 모델 버전 | 생성 모델 |
| 생성 시간 | 추천 생성 시각 |

추천 로그는 운영 분석 및 추천 품질 개선에 활용한다.

---

## 5-2. 추천 반응 로그

사용자의 추천 반응을 다음 기준으로 저장한다.

- 추천 클릭
- 상세페이지 이동
- 장바구니 추가
- 구매 완료
- 관심상품 등록

추천 로그와 행동 로그를 연계하여 추천 효과를 분석한다.

---

## 5-3. 추천 품질 모니터링

운영자는 다음 KPI를 상시 확인한다.

| 지표 | 설명 |
| --- | --- |
| CTR | 추천 클릭률 |
| CVR | 구매 전환율 |
| 추천 노출수 | 총 추천 노출 |
| 추천 생성 성공률 | 생성 완료 비율 |
| 평균 응답시간 | API 성능 |
| 캐시 적중률 | Cache Hit Rate |

기준치를 벗어나는 경우 운영 알림을 발생시키고 원인 분석을 수행한다.

---

## 5-4. AI 추천 상품 기능

- 사용자의 최근 활동 데이터를 기반으로 AI 추천 상품을 생성한다.
- 홈 화면 상단에 AI 추천 영역을 노출한다.
- 추천 결과는 행동 데이터 변경 시 자동으로 재생성한다.
- 추천 모델 버전이 변경되면 신규 추천 결과를 우선 적용한다.
- 사용자별 추천 상품은 최대 20개까지 생성한다.
- 동일 상품은 중복 추천하지 않는다.
- 추천 API는 캐시 데이터를 우선 조회한다.

- 변경 항목
- 변경 사유
- 적용 버전

# 06. 운영 관리 정책

## 6-1. 운영 모니터링

운영자는 다음 항목을 실시간으로 확인한다.

- 추천 생성 성공률
- 추천 실패 건수
- API 응답 시간
- 캐시 적중률
- 장애 발생 현황
- 추천 노출량
- 추천 클릭률

---

## 6-2. 장애 대응 프로세스

장애 발생 시 다음 절차를 따른다.

1. 장애 감지
2. 운영 알림 발송
3. 장애 원인 분석
4. 캐시 추천 전환
5. 서비스 정상화
6. 장애 보고서 작성

장애 종료 이후 운영 로그를 검토하여 재발 방지 대책을 수립한다.

---

## 6-3. 운영 지표 관리

추천 운영의 주요 지표는 일 단위로 집계한다.

| 지표 | 집계 주기 |
| --- | --- |
| CTR | Daily |
| CVR | Daily |
| 추천 생성 성공률 | Hourly |
| API 성공률 | Hourly |
| 평균 응답시간 | Hourly |
| 캐시 적중률 | Hourly |

월간 운영 보고서에는 주요 추이와 개선 사항을 함께 포함한다.

---

## 6-4. 운영 감사 정책

추천 정책 변경, 운영 설정 변경 및 관리자 작업은 모두 감사 로그로 저장한다.

감사 로그에는 작업자, 작업 시각, 변경 대상, 변경 전·후 값, 변경 사유를 기록하며, 운영 정책에서 정한 보관 기간 동안 유지한다.

---

## 6-5. 개인정보 보호 정책

추천 계산에 사용하는 사용자 행동 데이터는 개인정보 보호 정책에 따라 관리한다.

개인 식별 정보는 암호화하여 저장하며, 추천 모델은 필요한 최소 범위의 데이터만 활용한다.

운영자는 개인정보 조회 권한을 별도로 부여받은 경우에만 관련 데이터를 확인할 수 있다.

## 6-6. 운영 보고 체계

추천 서비스 운영 현황은 주간 및 월간 단위로 보고한다.

보고 항목은 다음을 포함한다.

- 추천 성능 변화
- 주요 KPI
- 장애 현황
- 정책 변경 이력
- 개선 과제
- 다음 운영 계획

# 07. 추천 기능 목적

## 7-1. 운영 목적

추천 기능은 사용자에게 관심 가능성이 높은 상품을 우선적으로 제공하여 상품 탐색 시간을 단축하고 서비스 이용 효율을 향상시키는 것을 목적으로 한다.

또한 사용자 행동 데이터를 지속적으로 반영하여 개인별 선호도에 적합한 추천 결과를 제공함으로써 서비스 이용 만족도를 높이고 탐색 과정의 일관성을 유지한다.

---

## 7-2. 기대 효과

추천 기능 운영을 통해 다음 효과를 기대한다.

- 개인 맞춤형 탐색 경험 제공
- 상품 탐색 시간 감소
- 추천 상품 클릭률 향상
- 구매 전환율 증가
- 서비스 체류시간 증가
- 재방문율 향상
- 추천 품질의 지속적인 개선

## 7-4. 성공 판단 기준

추천 기능은 아래 조건을 만족할 경우 안정적으로 운영되는 것으로 판단한다.

- 추천 생성 성공률이 목표치를 지속적으로 유지할 것
- 추천 응답 시간이 운영 기준을 만족할 것
- 주요 KPI가 목표 수준 이상을 유지할 것
- 장애 발생 시 대체 추천 정책이 정상 동작할 것
- 사용자 행동 데이터가 안정적으로 수집 및 반영될 것
- 추천 품질이 지속적으로 개선될 것
